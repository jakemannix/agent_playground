Single Agent Limitations

┌─────────────────────────────────────┐ │ Single Agent │ │ ┌─────────────────────────────┐ │ │ │ Context Window │ │ │ │ (Limited: ~200K tokens) │ │ │ └─────────────────────────────┘ │ │ │ │ • One set of tools │ │ • One model/personality │ │ • Stateless between sessions │ │ • No specialization │ └─────────────────────────────────────┘

  • Scalability - Distribute work across agents

MCP: Model Context Protocol

Agent-to-Tool Communication

Anthropic's open standard

What MCP Does

┌─────────────────────────────────────────────────┐ │ AGENT │ │ ┌───────────────────────────────────────────┐ │ │ │ LLM (Claude) │ │ │ └───────────────────────────────────────────┘ │ │ │ │ │ MCP Client │ └──────────────────────┼──────────────────────────┘ │ MCP Protocol ┌─────────────┼─────────────┐ ▼ ▼ ▼ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ fetch │ │ memory │ │ search │ │ server │ │ server │ │ server │ └─────────┘ └─────────┘ └─────────┘ Tools exposed to agent via standard protocol

MCP Tool Definition

{
  "name": "get_weather",
  "description": "Get current weather for a location",
  "inputSchema": {
    "type": "object",
    "properties": {
      "location": {
        "type": "string",
        "description": "City name"
      }
    },
    "required": ["location"]
  }
}

MCP Transports

  • stdio - Local process communication
  • SSE - Server-Sent Events over HTTP
  • Streamable HTTP - Direct HTTP calls
{
  "transport": "streamable_http",
  "url": "http://localhost:8123/mcp"
}

MCP Limitation

MCP = Agent ↔ Tool ┌─────────┐ ┌──────────┐ │ Agent │ ───────► │ Tool │ └─────────┘ └──────────┘ │ │ What about... ▼ ┌─────────┐ ┌─────────┐ │ Agent │ ───???─► │ Agent │ └─────────┘ └─────────┘ MCP doesn't define agent-to-agent communication!

A2A: Agent-to-Agent Protocol

Google's Open Standard

Released April 2025, now under Linux Foundation

A2A Design Principles

  • Embrace Agentic Capabilities
    Agents collaborate naturally, even without shared memory
  • Built on Existing Standards
    HTTP, SSE, JSON-RPC, gRPC
  • Secure by Default
    Enterprise-grade auth & authorization
  • Long-Running Task Support
    From quick tasks to hours-long workflows

A2A + MCP Together

┌───────────────────────────────────────────────────────┐ │ A2A Protocol Layer │ │ (Agent-to-Agent Communication) │ │ │ │ ┌─────────────┐ A2A ┌─────────────┐ │ │ │ Agent A │◄──────────►│ Agent B │ │ │ └──────┬──────┘ └──────┬──────┘ │ │ │ │ │ └─────────┼──────────────────────────┼─────────────────┘ │ MCP │ MCP ▼ ▼ ┌───────────┐ ┌───────────┐ │ Tools │ │ Tools │ └───────────┘ └───────────┘ MCP = Vertical (tools) A2A = Horizontal (agents)

Letta: Stateful Agents

Memory-First Architecture

From the MemGPT research paper

The Stateless Problem

Traditional LLM API: Request 1 Request 2 Request 3 │ │ │ ▼ ▼ ▼ ┌───────┐ ┌───────┐ ┌───────┐ │ LLM │ │ LLM │ │ LLM │ └───────┘ └───────┘ └───────┘ Each request starts from scratch! No learning, no memory, no growth

Letta's Stateful Architecture

┌──────────────────────────────────────────────────────┐ │ LETTA AGENT │ │ │ │ ┌─────────────────────────────────────────────────┐ │ │ │ In-Context Memory │ │ │ │ (Persistent across all interactions) │ │ │ └─────────────────────────────────────────────────┘ │ │ │ │ │ ┌──────────────────────┼──────────────────────────┐ │ │ │ Memory Tools │ │ │ │ ┌─────────┐ ┌──────────┐ ┌─────────────────┐ │ │ │ │ │ Read │ │ Write │ │ Search │ │ │ │ │ │ Memory │ │ Memory │ │ Archival Memory │ │ │ │ │ └─────────┘ └──────────┘ └─────────────────┘ │ │ │ └─────────────────────────────────────────────────┘ │ │ │ │ ┌─────────────────────────────────────────────────┐ │ │ │ External Memory (Vector DB) │ │ │ │ Conversation History + Archival Store │ │ │ └─────────────────────────────────────────────────┘ │ └──────────────────────────────────────────────────────┘

Memory Types in Letta

  • Core Memory - Always in context
    • User persona, agent persona, key facts
  • Recall Memory - Conversation history
    • Searchable, automatically managed
  • Archival Memory - Long-term storage
    • Vector DB for semantic search

Agent Self-Manages Memory

# The agent decides what to remember!

# Agent sees user preference and stores it
agent.send_message("I prefer dark mode interfaces")

# Internally, agent calls:
archival_memory_insert(
    "User prefers dark mode for interfaces"
)

# Later, when building UI:
results = archival_memory_search("user preferences")
# Returns: ["User prefers dark mode for interfaces"]

Multi-Agent in Letta

┌─────────────────────────────────────────────────────┐ │ Letta Multi-Agent System │ │ │ │ ┌─────────────────────────────────────────────┐ │ │ │ Shared Memory Layer │ │ │ │ (Agents can share memory blocks) │ │ │ └─────────────────────────────────────────────┘ │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │ Agent A │ │ Agent B │ │ Agent C │ │ │ │ (coder) │ │(reviewer)│ │(deployer)│ │ │ └─────────┘ └─────────┘ └─────────┘ │ │ │ │ Built-in mechanisms for communication │ │ and state sharing between agents │ └─────────────────────────────────────────────────────┘

Letta Agent Loop

# Each step is checkpointed to database!

while not done:
    # 1. Agent reasons about the task
    response = llm.generate(context + memory)

    # 2. Agent may use tools (including memory tools)
    if response.tool_calls:
        results = execute_tools(response.tool_calls)

    # 3. State is persisted (checkpoint)
    save_agent_state(agent_id, state)

    # 4. Continue until task complete
    done = response.is_complete

Comparison

When to Use What?

Protocol Comparison

Aspect MCP A2A Letta
Focus Agent ↔ Tool Agent ↔ Agent Agent State
Memory None Optional Core Feature
Discovery Tool schemas Agent cards API
Complexity Low Medium Medium
Best For Tool integration Agent orchestration Persistent agents

Use MCP When...

  • You need to connect an agent to external tools
  • Tools are the primary integration point
  • You want a simple, standardized tool interface
  • Building within a single agent context
// Example: Weather tool via MCP
{
  "transport": "streamable_http",
  "url": "http://localhost:8123/mcp"
}

Use A2A When...

  • Multiple specialized agents need to collaborate
  • Cross-organization agent communication
  • Long-running, complex workflows
  • You need enterprise security/auth
  • Building an agent ecosystem

Use Letta When...

  • Agent needs to learn and remember over time
  • Conversations span days/weeks/months
  • Personalization is important
  • Agent should improve through experience
  • You need reliable state persistence

MCP Tool Loading

# agent-factory/src/agent_factory/harness.py

async def create_mcp_tools(skills: List[MCPSkill]):
    """Load tools from MCP servers."""
    tools = []
    for skill in skills:
        # Connect to MCP server
        client = MultiServerMCPClient({
            skill.id: skill.mcp_config
        })
        # Get tools with auto-extracted schemas
        skill_tools = await client.get_tools()
        tools.extend(skill_tools)
    return tools

Architecture Patterns

Common Multi-Agent Designs

Pattern 1: Hub and Spoke

┌─────────────┐ │ Router / │ │ Supervisor │ └──────┬──────┘ │ ┌─────────────────┼─────────────────┐ │ │ │ ▼ ▼ ▼ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ Search │ │ Code │ │ Data │ │ Agent │ │ Agent │ │ Agent │ └─────────┘ └─────────┘ └─────────┘ Router receives all requests and delegates to specialized agents based on task type

Pattern 2: Pipeline

┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ Intake │───►│ Process │───►│ Review │───►│ Output │ │ Agent │ │ Agent │ │ Agent │ │ Agent │ └─────────┘ └─────────┘ └─────────┘ └─────────┘ Each agent handles one stage of workflow Results flow through the pipeline

Pattern 3: Peer-to-Peer

┌─────────┐◄────────────►┌─────────┐ │ Agent A │ │ Agent B │ └────┬────┘ └────┬────┘ │ │ │ ┌─────────┐ │ └───►│ Agent C │◄───────┘ └─────────┘ Agents communicate directly as needed No central coordinator A2A protocol enables discovery

Pattern 4: Hierarchical

┌─────────────┐ │ Manager │ │ Agent │ └──────┬──────┘ │ ┌─────────────────┼─────────────────┐ ▼ ▼ ▼ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ Team │ │ Team │ │ Team │ │ Lead A │ │ Lead B │ │ Lead C │ └────┬────┘ └────┬────┘ └────┬────┘ │ │ │ ┌────┴────┐ ┌────┴────┐ ┌────┴────┐ │ Workers │ │ Workers │ │ Workers │ └─────────┘ └─────────┘ └─────────┘

Key Takeaways

Remember These

  1. MCP = Agent talks to Tools (vertical)
  2. A2A = Agent talks to Agents (horizontal)
  3. Letta = Agent remembers everything (temporal)
  4. They're complementary, not competing
  5. Start simple, add complexity as needed

Getting Started

  • MCP: Use existing servers, define tool schemas
  • A2A: Expose /.well-known/agent.json, use task API
  • Letta: pip install letta, define memory blocks
